# Naive vs Structured 항목 단위 Recall 재분석 — 기존 주장 번복 기록

## 왜 다시 계산했는가

`04_검증결과.md`와 `06_종합정리.md`는 지금까지 "naive와 structured의 단순 발견 능력
차이는 크지 않다"고 결론 내렸습니다. 이 결론은 `results/naive_baseline_human_review.md`의
"① 변경사항 발견 6/7"과, `evaluate.py`가 자동 채점한 structured의 케이스별 Recall(0.75~1.0)을
나란히 놓고 비교한 것이었습니다.

그런데 이 두 숫자는 같은 기준으로 잰 게 아니었습니다.

- **naive의 "6/7"**: 케이스 단위 관대한 판정입니다. 한 케이스 안에서 일부 항목을 놓쳐도,
  치명적인 누락이 하나도 없으면 그 케이스 전체를 ✅로 셌습니다.
- **structured의 "0.75~1.0"**: 항목 단위 엄격한 비율입니다. `evaluate.py`가 GT의 `changes`
  배열 항목 하나하나를 `source_id`+`source_location`으로 정확히 매칭해야만 점수를 줍니다.

즉 관대한 잣대(naive)와 엄격한 잣대(structured)를 나란히 놓고 "차이가 크지 않다"고
말한 셈입니다. 같은 항목 단위 기준으로 naive를 다시 채점하면 어떻게 달라지는지 확인하려고
이 재분석을 했습니다.

## 방법

7개 실행 케이스 각각에서 GT의 `changes` 배열 항목(evaluate.py의 Recall 분모와 동일한
범위, unknown 항목은 제외)을 기준으로 삼았습니다. `results/baseline/TC-XX.txt`(naive의
자유 텍스트 출력)를 읽고, 각 GT 항목의 old→new 값과 방향이 텍스트에 실제로 정확히
등장하는지를 하나씩 대조했습니다. structured 쪽은 기존 `evaluate.py` 자동 채점 결과와
별도로, 자동 채점이 "미스"로 표시한 항목이 실제로는 내용이 맞는데 매칭 로직만 실패한
것인지(`results/structured/TC-XX.json` 원본 대조) 다시 확인했습니다.

## 결론 — 기존 주장을 이렇게 번복합니다

**기존 주장**(`04_검증결과.md`/`06_종합정리.md`의 원래 문구): "naive와 structured의 단순
발견 능력 차이는 크지 않다."

**재분석 결과**: 관대한 잣대와 엄격한 잣대를 같은 기준(항목 단위, 콘텐츠 정확성)으로
맞추면 naive 14/15(0.933)와 structured 14/15(0.933)로 **완전히 동률입니다.** "차이가
크지 않다"가 아니라 **"차이가 없다"**가 더 정확한 표현입니다.

이게 왜 중요한가 하면, structured의 두 "미스"(TC-03, TC-15)가 전부 매칭 로직의 한계였지
AI가 내용을 잘못 이해한 게 아니었던 반면, naive의 유일한 미스(TC-15 뇌혈관질환 보장
삭제)는 텍스트 어디에도 언급이 없는 **진짜 콘텐츠 누락**이었습니다. 반대로 structured의
유일한 진짜 콘텐츠 오류(TC-01)는 naive가 정확히 맞힌 바로 그 항목(뇌·심장 보장 삭제)이기도
합니다. 즉 둘 다 실수하는 지점이 다르지만 총량은 같습니다.

**그래서 이 프로젝트의 핵심 주장은 오히려 더 강해집니다.** "structured가 naive보다
정확하다"는 주장은 데이터가 뒷받침하지 않습니다(오히려 자동 채점 원점수만 보면 naive가
더 높아 보일 정도입니다 — 하지만 그것도 매칭 아티팩트 때문입니다). 이 프로젝트가 실제로
증명한 것은 정확도 우위가 아니라, **naive의 콘텐츠 오류(TC-15 완전 누락)는 사람이 7건을
전부 원문과 대조해야만 발견되는 반면, structured의 콘텐츠 오류(TC-01)는 평가기의 B4
규칙이 자동으로 검출했다는 것**입니다. 발견 능력이 동률이기 때문에, 오히려 "그 실수를
누가 자동으로 잡아내는가"라는 차이만 순수하게 남습니다.

## 이 재분석 자체의 한계

- naive 텍스트를 사람(실험자 1인)이 직접 읽고 판단한 것이라, evaluate.py의 M1/M2/M3처럼
  기계적으로 재현 가능한 절차는 아닙니다.
- GT `changes` 배열(unknown 항목 제외)만 대상으로 했습니다. naive와 structured의 unknown
  처리 능력 차이(`results/naive_baseline_human_review.md`의 ④ 추론 안 함 축)는 이미 크게
  갈렸고, 이 재분석은 그 축을 다시 계산하지 않았습니다.
- N=15개 항목(7케이스)이라 표본이 작습니다.
